# 约拍后端 API 规范

- 技术方向：Java 21、Spring Boot 3.x、Spring Security、MySQL、Flyway。
- 采用模块化单体；建议按 identity、photographer、portfolio、package、availability、request、booking、messaging、payment、admin 模块组织。
- REST API 使用 `/api/v1`；维护 OpenAPI 定义，分页、错误格式、校验和幂等约定保持一致。
- 所有写操作由服务端校验登录状态、角色、资源所有权、关系和状态迁移合法性。
- MySQL 金额存储使用整数最小货币单位或精确 DECIMAL，并明确舍入策略；不使用浮点数。
- 数据库更改必须包含 Flyway migration；外键、唯一键、索引和状态约束随迁移提供。
- 档期预约使用事务锁定相关摄影师/时段并再次查询重叠项，在同一事务中创建有效预约；正确处理冲突和重试。
- 私信首版仅支持文字。服务端按会话成员校验读取和发送权限；不实现图片、文件、附件或任意 URL 消息。
- 10% 定金比例由服务端计算；套餐快照保存在订单。摄影师保证金、退款和平台结算规则未定前，不实现真实资金扣收、冻结或划转。
- 支付集成须验签、幂等、查单、关单和记录渠道流水；以服务端确认结果更新订单，绝不信任客户端支付回调。
- 对象存储使用后端签发的最小权限短期凭证/签名；作品公开性与订单私密文件权限分别控制。
- 日志、错误响应、审计记录避免泄露凭证和敏感个人信息。
- 业务规则未定时明确标为阻塞或配置关闭，不自行创造交易规则。
