# 项目文档规范

- `约拍项目-MVP规格.md`记录产品已确认范围与待决策项；`约拍项目-开发计划.md`记录阶段、技术决策和验收路径。
- 已确认规则与建议/待决策规则要明确区分，不能把建议写成用户决定。
- 修改产品流程时，同步检查 MVP 规格、开发计划、总 `AGENTS.md` 及相关子目录规范是否冲突。
- API 设计文档存入 `openapi/`，与服务端接口保持一致。
- 可执行的产品/系统功能规格存入根目录 `specs/`，按 `specs/README.md` 的 SDD 工作流维护；不要只把需求留在聊天记录或代码注释中。
- 关键决定写明日期、决策内容、影响范围和未决事项；引用外部技术约束时优先链接官方文档。
- 中文为主，使用短标题和可执行条目；避免把整个规格重复复制到多个文档。
